| DEC-020 | Android screen capture pipeline | **MediaProjection → VirtualDisplay → codec input `Surface` → hardware H.264 `MediaCodec` (byte-buffer output) → JNI (`byte[]`) → Go core** (Spike 03 ratified; evidence: [results](spikes/03-android-mediaprojection-encoder-results.md)). **Bootstrap order is consent-first:** Activity `createScreenCaptureIntent()` → foreground service (`type=mediaProjection`) → `getMediaProjection` + `registerCallback` → `createVirtualDisplay`; starting the FGS before consent throws `SecurityException` on Android 15 at **both** targetSdk 34 and 35 (appop `project_media`, which only consent grants, is the gate). **Capture scope is requested explicitly** — the Android 15 dialog defaults to "A single app", so full-screen mirroring requires selecting "Entire screen" (`dumpsys media_projection`: `TYPE_SCREEN_CAPTURE`). **Codec chosen by capability** (`isHardwareAccelerated` + `areSizeAndRateSupported`), H.264 High primary (`c2.qti.avc.encoder` class), HEVC optional (present but unmeasured), **AV1 excluded** (software-only ≤ 1920 px on target devices). **Capture is damage-driven at panel refresh** (119–120 fps measured at 1080×2400 on SM7475/Android 15): `KEY_FRAME_RATE` and `Surface.setFrameRate()` do **not** throttle composition, so **Kotlin throttles to the negotiated stream rate** and Go **paces** a bursty source (0 fps on static content/screen-off is normal; a 39.6 Mbps one-second burst was measured on wake). **In-session adaptation** is limited to `PARAMETER_KEY_VIDEO_BITRATE` (applies, but loose — a 6000 → 2000 kbps change settled at ~3.4–3.7 Mbps, ≈1.8× the request, within ~1–2 s) and `REQUEST_SYNC_FRAME` (6–29 ms, p50 ≈ 22 ms); **resolution changes require a new session + new consent** (one VirtualDisplay per projection, single-use tokens, and re-binding a new encoder to a live VirtualDisplay did not resume delivery — 0 frames in two 3 s drains). `KEY_I_FRAME_INTERVAL` counts *configured-fps* frames (1 s @ 30 fps ⇒ a keyframe every 250 ms at 119 fps input), so it must be configured against the real capture rate. Encoder output is `byte[]` handed over the DEC-019 JNI boundary; SPS/PPS was observed in-band as one `CODEC_CONFIG` buffer and the output format exposes `csd-0`/`csd-1` keys (no payload bytes were dumped), so **byte-level framing (Annex-B vs AVCC) is unverified**. | `CONFIRMED` (Phase 0) — capture pipeline measured on a single mid-range SoC; Kotlin frame-rate throttling, Go-side pacing, HEVC encode path, and H.264 framing/CSD handoff remain to be validated in Spike 04 |
